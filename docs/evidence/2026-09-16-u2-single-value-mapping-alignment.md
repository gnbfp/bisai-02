# U2 开工前对齐卡：私聊归属的单值映射（§7.2 / §7.4）

> **目的**：§7.4 是数据地基 —— 归属判错是**静默串数据**（没有报错、没有异常，内容跑到别的组去）。
> U2 动手前把"键 / 刷新时机 / 没绑定怎么办 / 与迁移初值的关系"四件事钉死，改错代价最大。
> **谁签**：架构师（§7.4 的三条证据槽 + 本卡 §2 的 9 条决策）。开发按签字口径落地，不自行拍板。
> **现状依据（锚文本，不写行号）**：`src/gateway/app.py` 的 `_remember_group()`（现在写的是**全局单值** `state.group_chat_id`）、
> `src/gateway/vote.py` 的 `exempt()`（免 @ 白名单回退读同一个 `state.group_chat_id`）、`src/storage.py` 的 `mutate_raw()`（进程级锁）。
> **时间**：2026-09-16 起草，U2 开工前。

## 1. 我读到的规则（§7.2 的落地版）

| 情形 | 落点 | 我打算这么实现 |
|---|---|---|
| 该用户有绑定 | `index.user_last_group[sender_open_id]` | 用绑定的工作空间当 root，正常执行 |
| 从没在群里互动过 | 同上查不到 | 回 `replies.NEED_GROUP`，**不落盘、不起 pipeline**（沿用既有分支） |
| 在群里、但不在该群花名册里 | 沿用 | `PREFERENCE_NOT_MEMBER` / `PROPOSAL_NOT_MEMBER`，一字不改 |
| 绑定怎么刷新 | `_remember_group()` 换落点 | 任何**真实用户**的群消息 ⇒ `user_last_group[sender] = chat_id`；机器人自己的消息不算；**值没变不写盘** |

**为什么不用"你是哪个组的？"反问**（照抄 §7.2 的理由，便于下一轮复核）：L4 = 一个群一份作业 ⇒ 同一时刻只有一个"最近活跃工作空间"；私聊指令都是无状态即时指令，多一个状态机就多一处能把人卡住的地方。

## 2. 需要架构师点头的 9 条（每条我都给了倾向，请逐条勾）

1. **键 = `inbound.sender_open_id`**；"真实用户"= `sender_type == "user"`（`"app"` 排除）；**私聊消息不刷新绑定**（否则私聊自我指向）。倾向：**照此**。
2. **非花名册成员的群消息也刷新吗？** 倾向：**刷新**。绑定记的是"最近活跃在哪"这个事实，不是成员资格；非成员私聊时会撞上既有"不在花名册"文案，不会串数据。
3. **被 @ 门禁静默掉的群消息算互动吗？** 倾向：**算**（确实是"人在这个群说话"）。若要求"只有放行的才算"，请明说 —— 两种都自洽，但会改 §7.4 第 1 条证据槽的复现步骤。
4. **文件 / 图片消息算互动吗？** 倾向：**算**（同样是人发的）。
5. **写入口径**：`mutate_raw(index, fn)` + "**该键**的值没变就不写盘"（不是比较整份 doc）。
6. **`state.group_chat_id` 的处置**（§3.5 的待决项）：新布局下它是冗余字段。倾向：**保留但只读**（兼容 + 报告抬头 + `exempt()` 的回退），**不再作为 root 选择的依据**。请给一句结论。
7. **`vote.exempt()` 的回退**：`block["chat_id"]` 缺失时回退 `state["group_chat_id"]`。新布局下这个回退**要不要拆**？倾向：拆掉更干净，但那属于"动投票窗"，是否算 U2 范围请你定。
8. **迁移初值的语义**：`tools\migrate_workspace.py` 迁移时按 `members.json` 逐个填 `user_last_group[open_id] = 该群`（已实现、已演练，见 `docs\evidence\2026-09-16-migrate-workspace-tool-rehearsal.md`）。它是**一次性初值**，之后由运行时改写 —— 确认这个语义（迁移 ≠ "最近活跃"的推断）。
9. **自纠路径**：归属错了靠"回话里的来源标题"（`allocation.render_task_list()` 首行）+ 用户回群里发一句，**不加新指令**。确认。

## 3. 与 10 分钟穿透批的先后（硬约束）

**顺序**：穿透清单**先跑**，U2 **不许先动 `data-upgrade\`** —— 盘面一变（root 变成 `workspaces\<群>\`）就得重建环境。所以：本卡签字 → 穿透批 → U2 动盘。

三条清单项在**当前代码**里的期望（我预检过，都不需要改代码就能测，是"现状基线"）：

| 清单项 | 期望（现在的代码就是这么写的） | 要抓的证据 |
|---|---|---|
| ① 图片消息 | 群里：`router` 的图片分支直接 `Outcome()` ⇒ **静默**；私聊：回 `IMAGE_REJECTED` 短拒收，**且不入缓存**（D-45 ①：一张图不许挤掉刚发来的作业书 PDF） | 群 / 私聊各一条 `recv` 行 + 有没有 `-> ` 行 + `uploads\` 与 `state.json` 的 `pending_file` 有没有被动过 |
| ② 投票窗 × 群内裸数字 | `vote.exempt()` 只放行"**开窗那个群** + **花名册成员** + **纯数字**"；窗口冻住（`closed`）后不豁免；窗口一关 `awaiting`/`vote` 一起清、门禁立刻恢复 | 开窗后：成员裸数字（应计票）、非成员裸数字（应静默）、冻住后再发一条（应静默）+ `state.json` 的 `vote` 段前后 |
| ③ 投票中 `@作业书` | `router` 的 vote 分支明写"**不命中一律回退 7 条前缀**，窗口开着时「拆解」「作业书」必须照常干活"，且**到期的窗口先收口、再照原路走一遍**（不许吞指令） | `@作业书` 的 `recv` / `-> ` 行 + 是否出评分点 + 窗口没被吃掉 |

## 5. 架构师签字（2026-09-16）—— §2 的 9 条逐条勾/改

**签字前核过的代码事实**（都不是听说的）：`_remember_group()` 的谓词 = `sender_type == "app"` 排除 + `chat_type == "group"` + `chat_id` 非空 + **值没变就 return**；`storage.mutate_raw()` **无条件写盘**（fn 没改也会写）；`vote.exempt()` 与 `vote.accept()` 都写成 `block.get("chat_id") or state.get("group_chat_id")`；`vote.open_window()` 落块时**总是写 `chat_id`**。

| # | 结论 | 口径（照此实施） |
|---|---|---|
| 1 | ✅ **照此**（补一处谓词） | 键 = `inbound.sender_open_id`；判据照 `_remember_group()` 现有的三段：`sender_type == "app"` 排除、**`chat_type == "group"`**（别写成"不是私聊"）、`chat_id` 非空。私聊不刷新 ⇒ 同此 |
| 2 | ✅ **照此** | 非花名册成员也刷新：绑定记的是**事实**（最近活跃在哪），不是成员资格；非成员私聊撞上既有文案，不串数据 |
| 3 | ✅ **照此（算）** | 被门禁静默 ≠ 没互动。**理由要写进代码注释**：两者若绑一起，不 @ 的人永远建不了绑定 ⇒ 私聊永远 `NEED_GROUP`，等于把 §7.4 第 2 条证据槽的正常路径打断。**§7.4 第 1 条证据槽的复现步骤按这个改**：群里发一句（**无论是否被静默**）→ 私聊发指令 → 看来源 |
| 4 | ✅ **照此（算）＋硬约束** | 刷新必须放在 **app 层 `handle()` 里、`route()` 之前**。原因：文件 / 图片在 `route()` 第 1 段就 `return` 了（资源分支在门禁之前），刷新若写在文本路径里，**投过作业书的人反而建不上绑定** |
| 5 | ⚠️ **目标照此，落地方式改** | "该键的值没变就不写盘"**别在调用点实现**（读-比较-写是两步，锁外比较不原子）；改为在 `JsonStore.mutate_raw()` / `mutate_many()` 里做**锁内序列化比较：新值 == 旧值 ⇒ 不写盘**。通用、原子，且顺手把"没变化不写盘"变成全仓库规则。**回归**：传一个"原样返回"的 fn ⇒ 文件字节 / mtime 不变 |
| 6 | ✅ **保留但只读 + 标 deprecated** | 用途只留两条：迁移脚本的归属判据、旧数据兼容。**新写入路径一处都不许再写它**（写它 = 出两个真源）；并写明"它现在的值 = 迁移前的历史值"。`_remember_group()` 换落点后它自然停更 |
| 7 | ✅ **拆**（算 U2 范围） | `exempt()` 与 `accept()` 两处的 `or state.get("group_chat_id")` **都拆掉** —— `open_window()` 落的块**总是带 `chat_id`** ⇒ 那个回退是死代码，留着等于让全局单值继续对投票生效。**缺 `chat_id` ⇒ 不豁免 / 不算票**（宁静静默）。这是残留清理，**不改投票窗口的判定逻辑本身**。**回归**：块缺 `chat_id` ⇒ `exempt()` 返回 False |
| 8 | ✅ **照此**（语义写全） | 迁移写入的是**一次性初值**，口径 = "**花名册成员在该群**"，**明确不代表"最近活跃"**；重跑不覆盖运行时值（`merge_index()` 只补缺失键，已实现、已演练）。手册 / 卡里都按这句写 |
| 9 | ✅ **照此**（加一条可验证项） | 不加新指令；**但要求来源标题真的出现**：`allocation.render_task_list()` 的首行，且**私聊回话也要带** —— 否则用户在私聊里看不出归属错了，"自纠"就无从纠起。列进 §7.4 的证据槽 |
