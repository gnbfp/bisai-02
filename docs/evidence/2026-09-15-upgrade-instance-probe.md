## 5. 进程隔离：锁端口参数化（2026-09-15 复核）

手法：用一个模拟进程占住 47653（= MVP 的锁端口），再看升级版的单实例锁能不能拿到。

```
[A] GATEWAY_LOCK_PORT=47653 -> INSTANCE_PORT=47653  抢锁=False   <- 与 MVP 同端口，必被拒
[B] GATEWAY_LOCK_PORT=47654 -> INSTANCE_PORT=47654  抢锁=True    <- 换端口即可与 MVP 并存
[C] 真实入口 main() 在 47653 被占时：
    [M0] 启动被拒：已有一个网关实例在跑（单实例保护，P0-E）。
         同一套凭据跑两个进程 = 每条群消息被处理两次。请先关掉另一个窗口。
    exit=3
```

结论：`GATEWAY_LOCK_PORT` 生效（`src/gateway/app.py:62`）；**双进程并存的机制层已打通**。默认值仍是 47653 ⇒ MVP 行为零变化。
